# instabox-scheduler

本仓库是 **ACCT-A** 的实验仓库。ACCT-A 由 Muse（Muse_cr）独占
使用，账号为免费计划，5 台机器，test-1 至 test-5。

ACCT-B 由 tibo-cs 独占使用，各建各的仓库。两账号资源池完全
隔离，互不干扰；本仓库只记录 ACCT-A 的实验，以及已知的配对
复制协调信息。

## 协议

根本规范见 [PROTOCOL.md](PROTOCOL.md)，版本 1.3，日期 2026-10-24。
任何对协议的修改必须经人类负责人批准后生效。
仓库名称暂时不改，以后可能直接迁移或合并。

协议摘要：

- 本仓库是 ACCT-A 的仓库，已由人类负责人确认。
  每个智能体绑定并独占一个账号，一智能体一账号，凭证严格
  不交叉，不得借用、代操作或触碰另一账号。
- 实验登记表 CLAIMS.md 的职责是防工作重复 + 配对复制登记。
- 分工：ACCT-A → 主题 A（生命周期）、D（可靠性）、F/G
  （调度与跨账号观测）；ACCT-B → 主题 B（性能边界）、
  C（网络）、E（兼容性）。配对复制实验不受分工限制。
- 心跳是全天滚动循环，昼夜不对称：夜间 00:00–08:00 每 2 小时
  一轮，共 4 轮（00/02/04/06），最多 5 台全用；日间
  08:00–24:00 每 6 小时一轮，共 3 轮（08/14/20），最多 2 台，
  仅巡检轮与单机小脚印快测轮。
- 每轮聚焦一个主题，不贪多。同一实验在 3 个以上不同时段
  重复、结论稳定后，才可写入 scheduler-spec.md 为"已验证"。
- 长时实验（D3、B4、C3 等）跨轮"埋点"：埋设后状态保持
  "进行中"，注明埋设与预计收获时间，之后每轮探活，到点收获。
- 让位规则：人类真实任务永远优先。让位信号一出现，立即
  暂停或销毁实验占用的机器，实验状态改为"中止-让位"并注明
  让位时间与已获得的部分数据，释放 CLAIMS 登记，去执行人类
  任务。实验必须按"随时可被杀"设计。
- 实验记录只增不改；结论必须引用实验编号；性能指标必须
  给分布（p50/p95/max），禁止只报平均值。
- 红线：凭证严禁入仓；创建 / 销毁循环温和，间隔 ≥30 秒，
  每账号每天创建+销毁合计 ≤100 次，触顶后当天转入纯观测 /
  巡检轮；遇到拒绝 / 429 立即停止并记录，不得重试冲击；实验仅
  针对自己账号内的机器。

## 快速上手

1. 通读 PROTOCOL.md。
2. 确认自己的账号标签是 ACCT-A，并确认只持有该账号的凭证。
3. 复制 templates/experiment-template.md 备用。
4. 在 CLAIMS.md 登记你的第一个实验。
